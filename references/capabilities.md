# 能力覆盖参考清单

本清单用于确保每次代码分析覆盖全部关键维度。各阶段执行前对照本清单，防止遗漏。

## 十二维度覆盖 + 可选缺陷维度

| # | 维度 | 负责阶段 | 检查要点 |
|---|------|----------|----------|
| 1 | **架构模式** | S4 | 分层/微服务/微内核/事件驱动/CQRS 等 |
| 2 | **数据流** | S3 | 请求入口→处理→持久化的完整链路 |
| 3 | **安全设计** | S4 | 认证/授权/输入校验/沙箱/加密/审计 |
| 4 | **错误处理** | S4 | 异常体系/Error Code/Result 类型/fallback |
| 5 | **日志与监控** | S4 | 日志框架/日志级别/结构化日志/链路追踪 |
| 6 | **测试策略** | S2+S1 | 测试框架/覆盖率/单测集成测试比例 |
| 7 | **国际化(i18n)** | S1+S2 | i18n 框架/支持语言数/翻译文件组织 |
| 8 | **性能优化** | S5 | 缓存策略/异步处理/连接池/懒加载 |
| 9 | **依赖管理** | S1 | 依赖声明方式/版本锁定/安全审计 |
| 10 | **部署与运维** | S1 | Docker/K8s/CI-CD/环境变量管理/健康检查 |
| 11 | **配置管理** | S1+S2 | 配置文件格式/环境区分/敏感信息管理 |
| 12 | **API 设计** | S3+S4 | REST/GraphQL/gRPC/版本策略/限流/文档 |
| 13 | **缺陷与风险面**（可选） | S6B | 静态缺陷模式/失败路径覆盖/资源泄漏/并发安全/债务分级；**默认不执行**，仅用户勾选时启用 |

## 检查流程

```
S1 执行前 → 对照 #7 #9 #10 #11（项目级维度）
S2 执行前 → 对照 #6 #11（模块级维度）
S3 执行前 → 对照 #2 #12（数据流维度）
S4 执行后 → 对照 #1 #3 #4 #5（模式维度）
S5 执行后 → 对照 #8 #12（深挖维度）
S6B 执行前 → 对照 #13（缺陷与风险面，可选，仅用户勾选时启用）
S7 报告前 → 固定 12 项过一遍；若用户勾选缺陷扫描，连同 #13 一并检查
```

## 使用规则

- 如果某个维度在当前项目中不适用（如 CLI 工具无需国际化），在对应阶段的 `fallback_note` 中标注 `[SKIP] 原因`
- 如果某个维度在当前流程中被遗漏，在 S7 报告组的 `mandatory_sections_coverage` 中标注缺失
- **可选维度（#13）默认跳过**：除非用户在人工介入点明确勾选源码缺陷扫描，否则 S6B 不执行、#13 不检查——这是有意的 token 控制策略，不是遗漏
- **实测验证（S8）是能力驱动的可选原子**：仅当 `metadata.capabilities.can_execute_commands` 为真且存在 `[推演]` 结论/`external_unread` 依赖时才触发，用于把推演升级为实测；不满足条件时无任何降级义务，性能类结论维持 `[推演]` 标注
- 本清单是参考性而非强制性的——核心价值是**防止遗漏**，不是增加死板约束
